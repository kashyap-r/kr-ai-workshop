Why use StrEnum instead of Enum for SourceType and DocumentFormat?

Using StrEnum instead of Enum for SourceType and DocumentFormat provides several advantages:
1. String Representation: StrEnum members are represented as strings, which makes them more 
    readable and easier to work with when serializing or deserializing data, especially in 
    JSON or other text-based formats. 
    This is particularly useful when these enums are used in APIs or configuration files.
2. Comparison: StrEnum allows for direct comparison with strings, making it easier to check 
    the value of an enum member against a string without needing to access the .value attribute. 
    This can simplify code and reduce verbosity.
3. Type Safety: StrEnum still provides the benefits of type safety that come with using enums,
    ensuring that only valid values are used while still allowing for the convenience of string
     representation.
4. Interoperability: When working with external systems or libraries that expect string values,
 using StrEnum can improve interoperability and reduce the need for additional conversion 
 logic.

 Overall, using StrEnum enhances code clarity, maintainability, and ease of use when dealing 
 with enumerated types that are naturally represented as strings, making it a suitable choice 
 for SourceType and DocumentFormat in this context.
