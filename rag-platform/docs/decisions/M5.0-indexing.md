### What we plan to do ?
M4 built the embedding + vector store capability. M5 (this section) builds the actual indexing 
workflow around these capabilities. 

i.e. we're converting the emeddings to "indexed corpus".

So, the objective is therefore..
"Given a corpus of sourced documents, deterministically transform and persist its chunks and 
embeddings into the vector store so that the corpus can be queries reliably later.

It should answer the below questions..
    1. What exactly constitutes an index?
    2. What is the indexing unit?
    3. DocumentChunk
    4. How are chunk IDs generated?
    5. How do we avoid duplicate indexing?
    6. What happens when a document changes?
    7. What happens when a document is deleted?
    8. How do we know which version of a document produced an indexed chunk?
    9. What metadata must travel into Chroma?
    10. How do we rebuild the index?
    11. How do we validate that indexing actually succeeded?


THe scope of the current implementation is given below.. i.e. I implement only
    1. DocumentChunk → indexable record
    2. deterministic document_id
    3. deterministic document_hash
    4. deterministic chunk_id
    5. embedding generation
    6. Chroma upsert
    7. indexing summary
    8. a simple executable indexing script
