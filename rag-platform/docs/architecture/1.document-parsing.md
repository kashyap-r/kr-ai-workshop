
The architecture of the document parsing looks something like below... 
Starting Architecture.
             RAW
              │
              ▼
       Object Storage
       S3 / GCS / Blob
              │
            parse
              ▼
      PARSED ARTIFACT
              │
       ┌──────┴──────┐
       ▼             ▼
   Text/content    Metadata
   S3 / GCS / Blob   │
       │             │
       │             ▼
       │       DB / catalog /
       │       manifest etc.
       │
       ▼
    Chunking

The decision
    Persist parsed document content as a separate intermediate artifact.
    Raw source
        ↓
    ParsedDocument
        ↓
    persist parsed artifact
        ↓
    Chunking

For this prototype:
    data/raw/ZCompanyLLC/
            ↓
    data/processed/parsed/ZCompanyLLC/

The parsed artifact contains the actual extracted/normalized text, while provenance/
metadata is maintained separately as structured metadata associated with the 
ParsedDocument.

Production Analogy:
Prototype                         Production
────────────────────────────────────────────────────
data/raw/                         S3 / Blob Storage
data/processed/parsed/            S3 / Blob Storage
local metadata                    DB / catalog / manifest

The parsed text itself could be stored in:
    * S3 / GCS / Azure Blob — very common for durable artifacts
    * A document database such as MongoDB — possible, especially when content and 
    metadata are naturally document-shaped
    * A relational database such as PostgreSQL — possible, particularly when you need 
    transactional/queryable document management
    * A search/document system — depending on the architecture

The storage philosophy that can be followed.. 
Large/durable artifacts → object storage is very common.
Operational/queryable metadata → database/catalog.

And sometimes the parsed text and metadata are packaged together, e.g. a JSON/Parquet/
document record in object storage. That's an implementation choice.

Note: 
1. The mental model w.r.t the documents 
        Original file ≠ Parsed artifact ≠ Metadata ≠ Chunks

2. This separation will become particularly useful when we start experimenting with 
different chunking strategies against the same parsed corpus. We don't want to re-parse 
86 documents every time we change a chunking parameter.
