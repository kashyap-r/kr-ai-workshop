The parsed text itself could be stored in:
    * S3 / GCS / Azure Blob — very common for durable artifacts
    * A document database such as MongoDB — possible, especially when content and 
    metadata are naturally document-shaped
    * A relational database such as PostgreSQL — possible, particularly when you need 
    transactional/queryable document management
    * A search/document system — depending on the architecture

The storage philosophy that can be followed.. 
Large/durable artifacts → object storage is very common.
Operational/queryable metadata → database/catalog.

And sometimes the parsed text and metadata are packaged together, e.g. a JSON/Parquet/
document record in object storage. That's an implementation choice.

Normalization

- FUture enhancement 

Normalization is the process of cleaning and standardizing the parsed content before chunking, while preserving its original meaning and document structure.

Think of it this way:
- Parsing: Extracts content and structure from the source document.
- Normalization: Makes the extracted content consistent, clean and usable.
- Chunking: Divides the normalized content into meaningful, retrieval-friendly units.

Normalization is an important intermediate stage in a production RAG pipeline.
1. Why do we need normalization?

Consider a PDF containing:
    5.1    Annual Leave

    Employees are entitled to paid annual leave
    based on their employment location.


    India:

    • Employees are entitled to 20 working days
    of annual leave per calendar year.

    • Leave must be requested through the HR portal.


A PDF parser might extract it as:
    5.1    Annual Leave

    Employees are entitled to paid annual leave
    based on their employment location.

    India:

    (cid:127) Employees are entitled to 20 working days
    of annual leave per calendar year.

    (cid:127) Leave must be requested through the HR portal.

There are several problems:
- Excessive blank lines.
- Inconsistent whitespace.
- Incorrect bullet character encoding.
- Unnecessary line breaks.
- Potentially inconsistent heading formatting.
If we directly feed this to the chunker, we may produce poor-quality chunks.

Normalization addresses these problems.

2. What exactly happens during normalization?
I would divide normalization into these operations:
Operation	                What it does	                                    Example
Whitespace normalization	Removes excessive spaces and blank lines	        Multiple blank lines → one
Unicode normalization	    Standardizes equivalent Unicode representations	    Different apostrophe encodings
Character correction	    Fixes known extraction artifacts	                (cid:127) → •
Line-break normalization	Rejoins lines broken by PDF layout	                Sentence fragments → complete paragraph
Header/footer handling	    Identifies repeated page boilerplate	            Removes repeated company footer
Hyphenation correction	    Rejoins words split at line boundaries	            employ-\neement → employment
Text encoding cleanup	    Removes invalid or unwanted control characters	    Removes non-printable artifacts
Structural normalization	Standardizes headings, lists and tables	            Consistent element types
Metadata normalization	    Standardizes metadata fields and values	            ßCountry codes, dates, language

One important distinction: normalization should not indiscriminately remove information. For example, page numbers, legal references, table values and meaningful symbols may be important for retrieval and citations.

Let's use the same fictional employee handbook.

Notice that we have improved readability without changing the meaning or losing the heading structure.

                            │

                Embedding & Indexing

Important: normalization should preserve structure

Normalization should clean the actual list items while preserving:
- Element ID.
- Element type.
- Parent relationship.
- Heading hierarchy.
- Page number.
- Sequence number.
It should not flatten the entire document into a string and reconstruct the hierarchy later.

Also, normalization should be idempotent: running it twice should not continue changing the document.

We should/ can implement two normalization strategies:
1. Text normalization: Clean text and correct extraction artifacts.
2. Structure normalization: Validate and standardize the parsed element hierarchy.
Later, we can add source-specific normalization for PDF, HTML, DOCX and Confluence.

One architectural decision worth recording: Parsing extracts what the source contains; normalization standardizes the extracted representation without changing its meaning; chunking determines how that representation is divided for retrieval.
