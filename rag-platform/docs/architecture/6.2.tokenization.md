### Tokenization 

#### 1. Where does tokenizing fit into the RAG?

It is important to understand the distinction between document chunking, tokenization, and query embedding.

The short answer:
- Knowledge base documents: Parsed → Chunked → Tokenized internally by the embedding model → Embedded → Indexed.
- User query: Understood/normalized if necessary → Tokenized internally by the embedding model → Embedded → Used for retrieval.
We generally do NOT chunk a user query the way we chunk knowledge-base documents.

Let's walk through it using our ZCompanyLLC HR knowledge base.
1. Document processing vs query processing
Consider a knowledge-base document containing 10,000 characters.

We split it into manageable chunks because:
- Documents can be very large.
- Embedding models have input token limits.
- Smaller passages provide more focused retrieval units.
- We want to retrieve relevant passages rather than entire documents.

#### 2. What exactly is Tokenization?

Tokenization is the process of converting text into smaller units called tokens, which a model can process.

A token is not necessarily a word.

Depending on the tokenizer, a token can represent:
- A complete word.
- Part of a word.
- Punctuation.
- Whitespace or other text patterns.

For example, consider:
    What is the maternity leave policy in India?

A simplified illustration of tokenization might look like:
    "What" " is" " the" " maternity"
    " leave" " policy" " in" " India" "?"

The actual token boundaries depend on the model's tokenizer. This is just illustrative.

The tokenizer converts these tokens into numerical token IDs:
Text
  |
  v
Tokenizer
  |
  v
Token IDs
  |
  v
[2054, 2003, 1996,  ...]

Those IDs are then passed into the model.

The model processes them and produces vector representations.

Tokenization vs embedding
These are two different operations.
Tokenization	                        Embedding
Converts text into token IDs	    Converts text into numerical vectors
Uses a tokenizer	                Uses an embedding model
Produces discrete IDs	            Produces continuous numerical values
Prepares text for model processing	Represents semantic information
